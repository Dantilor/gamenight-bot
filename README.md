# GameNight Host Telegram Bot

Telegram-бот `@GameNightHostBot` для Mini App GameNight Host. Рабочий процесс — webhook, без long polling. Точка входа production: `server/src/main.ts` (`npm start` запускает `dist/main.js`).

Бот сохраняет текущие команды:

- `/start` — текстовое приветствие «Ваш вечер начинается прямо сейчас! ✨» и кнопка «🎮 Играть в Mini App»
- `/play` — то же приветствие с картинкой и кнопка «🎮 Открыть GameNight Host»
- `/ping` — `pong`
- уведомление об окончании Premium и кнопка «Продлить подписку»

Картинка `server/public/hero-new.png` используется только командой `/play` и отдаётся как `/public/hero-new.png`. В режиме `api` бот загружает файл сам и при ошибке отправки фото отвечает текстом. В режиме `webhook` Telegram скачивает публичный HTTPS-адрес этой картинки. `/start` всегда отвечает текстом, даже если файл на месте.

Premium читается из PostgreSQL основной игры (`subscriptions.active_until`, `plans`). Бот не создаёт платежи и не меняет даты подписок. Оплата остаётся в Mini App и YooKassa. Страница продления — маршрут фронтенда `/premium`. Тарифы запрашиваются у `GET /api/plans`.

## Сборка и запуск

Нужен Node.js 22.

```bash
npm ci
npm run build
npm start
```

Timeweb App Platform:

- Framework: Express
- Runtime: Node.js 22
- Build command: `npm run build`
- Start command: `npm start`
- Health check: `/health`

`GET /health` возвращает HTTP 200 и `{"ok":true,"ready":true}`, когда HTTP-сервер готов принимать webhook. Это не означает, что webhook уже зарегистрирован в Telegram.

`GET /health/db` отвечает только при заголовке `X-Health-Token`, совпадающем с `HEALTHCHECK_TOKEN`. В ответе нет строки подключения.

## Безопасный старт

Пока идёт проверка на Timeweb, оставьте:

```bash
ENABLE_WEBHOOK_REGISTRATION=false
ENABLE_SUBSCRIPTION_NOTIFICATIONS=false
```

При `ENABLE_WEBHOOK_REGISTRATION=false` процесс не вызывает `setWebhook`. Остановка процесса webhook не снимает. Регистрация выполняется только в режиме `api`, при флаге `true` и только на `https://` адрес из `PUBLIC_URL` + `BOT_WEBHOOK_PATH`.

## Режим ответа

`TELEGRAM_REPLY_MODE=api` — поведение по умолчанию. Ответы уходят отдельными запросами на `https://api.telegram.org`.

`TELEGRAM_REPLY_MODE=webhook` отвечает на входящий webhook одним JSON-методом Bot API в HTTP 200. Так устроен официальный ответ при получении обновления: https://core.telegram.org/bots/api#making-requests-when-getting-updates. Этот режим не вызывает `getMe`, `setWebhook` и не передаёт обновление в Telegraf. Включения `webhookReply` у Telegraf недостаточно: перед обработчиком библиотека вызывает `getMe`, а `sendMessage` и `sendPhoto` всё равно уходят отдельным HTTP-запросом.

В режиме `webhook`:

- `/ping` — один `sendMessage` с текстом `pong` и снятием reply-клавиатуры в том же методе.
- `/start` — один `sendMessage` с HTML-текстом и кнопкой `web_app` на `MINI_APP_URL`. Картинка не прикладывается. Параметр deep-link команду не ломает и в ответ не копируется.
- `/play` — один `sendPhoto` с тем же текстом в подписи и своей кнопкой. Фото — `https://<PUBLIC_URL>/public/hero-new.png`. Если заранее нет файла, `PUBLIC_URL` не является https без логина и пароля или `MINI_APP_URL` нельзя использовать как https-кнопку, ответ готовится как `sendMessage`. Повторной отправки после `sendPhoto` нет: Telegram не возвращает результат этого метода.
- Кнопка `web_app` ставится только в личном чате.
- В группе команда с `@именем` не обрабатывается: без `getMe` имя бота неизвестно. Команда без `@имени` обрабатывается, но кнопка `web_app` туда не ставится.
- Отдельные запросы на удаление прошлого приветствия и на пустое сообщение со снятием клавиатуры не выполняются.
- `renew_subscription` — один `sendMessage` с тарифами `GET /api/plans` и кнопкой на `/premium` в личном чате. `answerCallbackQuery` не отправляется, поэтому индикатор нажатия Telegram сам не гасит. `message_id` не сохраняется.
- Неизвестное обновление завершается пустым HTTP 200 и наружу к Telegram не идёт.
- `ENABLE_WEBHOOK_REGISTRATION=true` и `ENABLE_SUBSCRIPTION_NOTIFICATIONS=true` в этом режиме не выполняются. Процесс пишет, что регистрация и рассылка невозможны, и не сообщает об успехе. Уже установленный webhook не снимается.

При `ENABLE_SUBSCRIPTION_NOTIFICATIONS=false` сообщения о подписках не отправляются. Перед включением примените миграцию от имени владельца базы:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f server/db/migrations/001_bot_subscription_expiry_notices.sql
```

Либо, тем же владельцем: `npm run migrate`.

Роли бота достаточно `SELECT` на `plans` и `subscriptions` и `SELECT/INSERT/UPDATE` на таблицы уведомлений. Права на изменение подписок ей не выдавайте. Первый запуск с включёнными уведомлениями записывает уже наступившие окончания как исторические и не рассылает их.

## Админ-панель рассылок

`/admin` открывается только у `BROADCAST_ADMIN_ID` и только в личном чате. Остальным бот отвечает, что команда недоступна, и не показывает меню. Webhook и секрет не меняются. Процесс бота не запускает массовую отправку при старте.

Информационная рассылка берёт `telegram_id` из существующей таблицы `users`. Команда `/subscribe` для неё не нужна, и в приветствие кнопка подписки не добавляется. `/unsubscribe` записывает отказ, и такой человек в следующие рассылки не попадает. Если Telegram отвечает, что бот заблокирован или чат недоступен, этот ID тоже исключается из следующих попыток. Наличие строки в `users` само по себе доставку не гарантирует.

Рекламная аудитория отдельно и по-прежнему требует предварительного согласия кнопкой. Этот режим не разрешает рекламу без согласия.

Кнопка «🚀 Отправить пользователям» сначала показывает число получателей. Без подтверждения очередь не создаётся. Повторное подтверждение не дублирует получателей. «🧪 Отправить тест себе» ставит в очередь одно сообщение только администратору.

### Кнопки кампании

Для каждой кампании кнопка «🔘 Кнопки» переключает режим: «Mini App» (по умолчанию, как у прежних кампаний), «сайт и Mini App», «сайт». Сайт — обычная URL-кнопка «🌐 Открыть новый сайт», Mini App — `web_app` «🎮 Играть в Mini App» с `MINI_APP_URL`. Предпросмотр и worker собирают клавиатуру одним кодом (`server/src/broadcastButtons.ts`). Режим и адрес сайта хранятся в черновике и в кампании; уже созданные кампании остаются в режиме Mini App.

### Шаблон «запуск WEB»

Кнопка «📋 Шаблон: запуск WEB» подставляет готовый рекламный текст, аудиторию «реклама» и обе кнопки (сайт с UTM `web_launch_20261127` и Mini App). Она ничего не отправляет и не ставит в очередь. Текст проверяется как Telegram HTML (теги, экранирование, длина после разбора сущностей); с фотографией подпись не длиннее 1024 символов, иначе отправляйте текстом.

Массовая очередь блокируется центральной проверкой `evaluateMassSendGate` (и в панели, и при `queueMass`):

- тип кампании `ads` проверяется отдельно от текста;
- рекламный анонс сайта распознаётся по нескольким маркерам, поэтому правка одной строки или переключение на `notify` защиту не обходит;
- для любой `ads`-кампании нужна явная пометка «Реклама» (или erid) — без неё очередь не создаётся;
- пока `claimsVerified` в `server/src/broadcastPresets.ts` равен `false`, текст с неподтверждёнными утверждениями (колесо фортуны, 16 игр, 15 000 вопросов и т.п.) в очередь не ставится;
- тест себе по-прежнему можно.

### Шаблон «Обновление WEB-версии» (баннер, текст, две кнопки)

Кнопка «📋 Шаблон: Обновление WEB-версии» подставляет текст в Telegram HTML (жирный через `<b>`, подпись 633 символа при лимите 1024), аудиторию `notify` и обе кнопки: «🌐 Открыть WEB-версию» (обычная URL-кнопка, UTM `web_update_20261127`) и «🎮 Играть в Mini App» (`web_app`, `MINI_APP_URL`). Порядок в `/admin`: шаблон, затем «🖼 Добавить фотографию» и отправить баннер в чат с ботом — сохраняется его `file_id` (самый большой размер). Рассылка уходит как `sendPhoto` с HTML-`caption`.

Аудитория `notify`: все из `users`, кроме отписавшихся, заблокировавших бота и недоступных чатов; `ads_opt_in` не требуется. Тест себе уходит только администратору.

Массовая очередь для этого текста заблокирована, пока не подтверждены утверждения (колесо фортуны, больше вопросов, Premium и оплата через браузер, восстановление Premium, «без VPN»); проверка — `findUnverifiedClaims` в `server/src/broadcastPresets.ts`, флаг `claimsVerified`. Тест владельцу при этом доступен. Прежний рекламный текст в `notify` не отправляется.
Один и тот же текст не уходит человеку дважды: уже получившие (`sent`/`sending`) этого точного текста не попадают в новую кампанию даже под новым токеном подтверждения, а число получателей в панели это учитывает.

Перед каждой фактической отправкой mass-кампании worker заново проверяет согласие, `/unsubscribe` и блокировку бота. Остановка кампании и защита от повторной доставки сохранены. Оценку требований закона о рекламе делает владелец; пока маркировка и факты не подтверждены, массовую отправку не запускайте.

### Worker

`npm run broadcast-worker` без режима ничего не делает и не обращается к базе. Режимы:

- `-- --check` — только `getMe`, ничего не отправляет;
- `-- --status` — только чтение: готовность таблиц, размеры аудиторий, очередь (без Telegram ID);
- `-- --only-test` — отправляет только тестовые кампании, массовую очередь не трогает;
- `-- --send-mass` — отправляет тестовые и массовые кампании, запускать только после отдельного подтверждения владельца;
- `-- --max-sends=N` — необязательный предел сообщений за запуск.

Темп по умолчанию — одно сообщение каждые 60 мс (около 16 в секунду). Ответ 429 worker переживает: ждёт `retry_after`, возвращает попытку получателю и после 25 подряд ответов 429 останавливает запуск, сохраняя очередь. Ошибка 400, не связанная с блокировкой, помечает получателя как `failed` без повторов. `message_id` сохраняется, статус `sent` ставится только после него.

Доступ к Telegram без отправки проверяется командой `npm run broadcast-worker -- --check`. Доставка выполняется там, где открывается `https://api.telegram.org` и есть доступ к базе (например, на компьютере владельца). На Timeweb в режиме `webhook` этот процесс запускать не нужно: исходящее соединение с Telegram там не подтверждено, и worker не должен помечать сообщения отправленными без `message_id`. Остановка через «🛑 Остановить рассылку» не даёт worker взять оставшиеся сообщения.

Перед включением владелец базы делает резервную копию и применяет миграции по порядку. Пример для PostgreSQL:

```bash
# 1) Резервная копия (обязательно до ALTER)
pg_dump "$DATABASE_URL" --format=custom --file="gamenight-bot-backup-$(date +%Y%m%d-%H%M%S).dump"

# 2) Миграция таблиц рассылки (если 002 ещё не применялась)
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f server/db/migrations/002_bot_broadcast.sql

# 3) Кнопки кампании (безопасные ADD COLUMN IF NOT EXISTS)
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f server/db/migrations/003_bot_broadcast_buttons.sql
```

Миграция 003 только добавляет `button_mode` и `web_url` в `bot_broadcast_drafts` и `bot_broadcast_campaigns` с default `miniapp`. Существующие кампании сохраняют прежнее поведение. Таблицы Premium, payments, users, WEB и Mini App не затрагиваются. Пока 003 не применена, панель отвечает, что таблицы не готовы, и ничего не отправляет.

Точное число допустимых получателей анонса (только ads-согласие, без отписки и без блокировки) смотрите read-only:

```bash
npm run broadcast-worker -- --status
```

В ответе поле `eligibleAdsRecipients`. Telegram ID не печатаются.

Роли бота нужны чтение и запись только в новые таблицы `bot_broadcast_*` и `SELECT (telegram_id)` на `users`. Права на изменение `users`, `subscriptions`, `payments` и `plans` ей не выдавайте.

## Команды и меню BotFather

`/site` отвечает сообщением о сайте и обычной HTTPS-кнопкой «🌐 Открыть сайт» на `https://play.gamenighthost.ru/` (не `web_app`). Он работает и в режиме `api`, и в режиме `webhook`. В режиме `webhook` ответ уходит одним методом `sendMessage` в HTTP-ответе, без исходящих запросов к Telegram.

`/subscribe` снимает отказ от информационных сообщений бота и показывает кнопку согласия на рекламу. `/unsubscribe` записывает отказ и отзывает согласие на рекламу. Информационные рассылки идут и без `/subscribe`, если человек не отказался.

Список для BotFather (`/setcommands`), вносится вручную после деплоя. `/admin` в него не входит:

```
start - Главное меню
play - Играть в Telegram
site - Открыть сайт GameNight Host
subscribe - Включить новости бота
unsubscribe - Отключить новости бота
```
